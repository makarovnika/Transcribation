# evaluator-rubric.md — рубрика проверки фичи

> Используется при оценке того, можно ли пометить фичу `passing`.
> Если хотя бы один пункт «нет» — фича не готова.

## Универсальные критерии (любая фича)

| # | Критерий | Как проверить |
|---|----------|---------------|
| 1 | Код соответствует `spec` из `feature_list.json` | Прочитать spec, сверить с реализацией |
| 2 | `./init.sh` отрабатывает | Запустить, прочитать exit code |
| 3 | Тесты, упомянутые в `verification`, реально написаны и проходят | `pytest -v <путь>` |
| 4 | `evidence` в `feature_list.json` ссылается на конкретные команды/файлы | Не «протестировано», а «pytest tests/test_x.py — все 7 passed» |
| 5 | Нет регрессии в других фичах | `pytest tests/` целиком |
| 6 | Не нарушены принципы из `CLAUDE.md` (типизация, обработка ошибок, логи) | Code review |

## Специфичные критерии

### Транскрибация (F03)
- На 30-секундном WAV возвращает ≥1 сегмент.
- Сегменты имеют монотонно неубывающие `start`.
- При language=auto определяется русский для русского файла.

### Диаризация (F04)
- На 2-голосовом файле возвращает ≥2 уникальных метки.
- Без HF-токена → понятная ошибка, а не KeyError.

### Alignment (F05)
- Сегмент целиком внутри одного speaker-интервала → этот спикер.
- Сегмент пересекает 2 интервала → тот, с кем больше перекрытие.
- Сегмент без перекрытий → `None` или `UNKNOWN`, не падение.

### Экспортёры (F06)
- SRT: формат таймкода `HH:MM:SS,mmm` (запятая!), нумерация с 1.
- VTT: начинается с `WEBVTT\n\n`, таймкод `HH:MM:SS.mmm` (точка!).
- JSON: валидный, парсится `json.loads`, есть все поля.
- TXT: метки спикеров в квадратных скобках.
- MD: заголовки спикеров через `##`.

### UI (F08)
- Все элементы из ТЗ §3.1 присутствуют.
- На сломанном файле — ошибка в UI, не traceback.
- Прогресс обновляется (хотя бы по фазам: «загрузка → транскрибация → диаризация → готово»).
