# Handoff-промпт для Claude Code

> Это первое сообщение, которое нужно дать Claude Code (или другому агенту),
> чтобы он начал работу по v2. Просто скопируй текст ниже в чат.

---

## Промпт (скопировать целиком):

```
Привет. Открой репозиторий transcriber/ и прочитай по порядку:

1. CLAUDE.md — правила работы и operating loop.
2. claude-progress.md — где мы остановились (v1 закрыт после F01-F08).
3. TZ-v2-improvements.md — полное ТЗ на v2 со всеми деталями каждой фичи.
4. feature_list-v2.json — обновлённый список фич (заменяет текущий feature_list.json).
5. outputs/ui-mockup.html — визуальный мокап нового UI (открой в браузере для понимания).

После прочтения:

A. Замени feature_list.json содержимым feature_list-v2.json (это новый источник
   правды по статусу фич).

B. Удали feature_list-v2.json (он был промежуточным).

C. Запиши в claude-progress.md новую сессию с пометкой "v2 kickoff: получено ТЗ,
   фичи F11-F29 добавлены, начинаю с F27".

D. Запусти ./init.sh, убедись что smoke pytest зелёный.

E. Начни работу с фичи F27 (cross-platform RAM detection) — она самая
   изолированная и быстро покажет, что цикл работает. После F27 → F11 (фундамент
   для большинства остальных).

ВАЖНО (из CLAUDE.md):
- Одна активная фича за раз. Не открывай F28, пока F27 не passing.
- Перед каждым коммитом — pytest tests/ -q зелёный.
- Не помечай фичу passing без реально прогнанной верификации и evidence.
- Уровень Python у меня базовый — объясняй на русском что/почему/что проверить.
- Не ослабляй тесты и не переписывай feature_list.json, чтобы скрыть
  незавершённую работу.

Каждая фича в ТЗ имеет полную спецификацию (§F11..§F29 в TZ-v2-improvements.md):
файлы, верификацию, edge cases. Если что-то непонятно или конфликтует с
текущим кодом — спрашивай меня до того как писать код.

Начинай.
```

---

## Что произойдёт:

1. Claude Code прочитает все 4 документа.
2. Применит новый feature_list.json (теперь там 19 фич вместо 10).
3. Запишет новую сессию в claude-progress.md.
4. Прогонит smoke-тесты.
5. Возьмёт F27 (psutil вместо sysctl — 30 минут работы).
6. Когда F27 пройдёт верификацию — перейдёт к F11 (переименование спикеров).
7. И так далее по графу зависимостей из §4 ТЗ.

## Если хочешь начать с другой фичи:

Замени в промпте "E. Начни работу с фичи F27" на нужный ID. Например, если
хочется сначала визуальные изменения — `F13-ui-redesign`. Но учти зависимости:

- **F11** — фундамент для F12, F14, F17, F18, F19, F22, F23. Без него многое
  не построить.
- **F13** — изолированный от данных, но затрагивает весь app.py.
- **F27** — bugfix, не зависит ни от чего.
- **F15** — изолированно (только audio_utils + чекбокс).

## Если ТЗ нужно подредактировать перед запуском:

Все детали — в `TZ-v2-improvements.md`. Каждая фича — отдельная секция (§F11 –
§F29) с собственной spec/verification/файлами. Менять можно прямо в файле, потом
дать Claude Code обновлённую версию.
