# AGENTS.md — правила работы агента

> Этот файл — операционные правила для любого ИИ-агента (Claude Code, Cursor, etc.),
> работающего в репозитории. Технический контекст см. в `CLAUDE.md`.

## Принципы

1. **Не имитируй прогресс.** Если фича не работает — статус `blocked`, не `passing`.
2. **Одна фича за раз.** Параллельно — только тогда, когда задачи независимы и это явно даёт выигрыш.
3. **Источник правды — артефакты в репо**, а не чат. Любое решение фиксируется в файле.
4. **Перед стартом** — `./init.sh` и проверка smoke-тестов.
5. **Перед финишем** — обновить `claude-progress.md`, `feature_list.json`, `session-handoff.md`.

## Что нельзя делать молча

- Менять рубрику оценки (`evaluator-rubric.md`) под удобный результат.
- Удалять или ослаблять тесты, чтобы они проходили.
- Отключать `vad_filter` / `condition_on_previous_text` / `beam_size` без записи в `claude-progress.md` причины.
- Коммитить `.env`, HF-токены, файлы из `outputs/`, `cache/`.

## Что нужно делать явно

- Если фича упирается в внешнее (HF-токен, отсутствующая модель, лимит памяти) — `blocked` + запись блокера в `session-handoff.md`.
- Если в ходе работы обнаружено несоответствие ТЗ — зафиксировать в `claude-progress.md` и спросить пользователя.
- Если меняется формат экспорта или поведение UI — обновить README.

## Definition Of Done (короткая версия)

Фича готова, когда:
- [ ] Код реализован.
- [ ] Тесты (если предусмотрены) написаны и **реально проходят**.
- [ ] `./init.sh` отрабатывает без ошибок.
- [ ] Evidence (что и как проверено) записан в `feature_list.json` → `evidence`.
- [ ] `claude-progress.md` обновлён.
